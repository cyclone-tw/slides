10-minute HTML briefing 2026-06-21 Cyclone / Codex

Cyclone-Wiki Core

給人和 AI Agent 共用的長期工作記憶。這份 10 分鐘簡報用白話說明它目前的功能、設定、可使用的 Agent，以及後續規劃。

01 / 為什麼存在

它是 AI 的長期工作記憶

Cyclone-Wiki Core 不是一般筆記本，而是給人和 AI Agent 共用的長期知識庫。

Agent 指的是會讀資料、執行任務的 AI 工作角色。repo 指的是有版本紀錄的專案資料夾。這個 repo 保存操作知識、流程、決策、專案脈絡與輸出 metadata，讓下一個 Agent 不必從零開始。

像圖書館重要知識有固定位置，不只留在一次對話裡。
像交接站不同 Agent 接手時，可以先讀同一份規則和背景。
像工作記憶保留可重複使用的事實、流程、決策與警戒線。

02 / 解決的問題

讓知識不要散落在各處

如果知識只留在聊天紀錄、不同機器、Google Drive、GitHub issue 或 runtime 裡，下一次工作就會重複摸索。

Cyclone-Wiki Core 把能長期使用的內容收進同一個可搜尋、可驗證的地方。runtime 是實際跑服務的環境；它的狀態可以被記成摘要，但私密原始資料不進 core repo。

以前容易發生現在的做法
重要決策卡在某次對話Decision note 保存為什麼這樣做
流程藏在某台機器Procedure note 保存怎麼做
Agent 不知道先讀哪裡AGENTS、Soul、startup brief 是入口
搜尋靠記憶和運氣QMD 和 rg 幫忙找本機 Markdown
[S2][S3][S6][S8]

03 / 目前能做什麼

用簡單格式，撐起可驗證的系統

目前核心能力是 Markdown、Git、QMD 和 validation scripts。

Markdown 是好讀的純文字筆記格式。Git 是追蹤修改紀錄的系統。QMD 是本機搜尋層，像幫 wiki 做索引的搜尋工具。validation scripts 是檢查腳本，負責在送出前檢查格式和隱私風險。

Markdown人看得懂，Agent 也容易讀。
Git知道誰改了什麼，也能回頭檢查。
QMD讓 Agent 在動手前先查舊知識。
Validation scriptswiki-lint 和 privacy-scan 先擋掉明顯問題。
[S1][S2][S8][S18]

04 / 知識怎麼進來

先進 inbox，再升格成正式知識

Cyclone-Wiki 採 inbox-first：先把原始或半整理內容放進 _inbox，確認後才升格。

_inbox 像收件匣，保存 source note，也就是來源材料。正式 note 像書架上的分類書，包含 Procedure、Decision、Project、Synthesis 等穩定知識。

階段白話說明常見結果
Capture先把值得保留的素材收起來_inbox/ Source note
Review確認內容可靠、沒有越界可引用或待整理
Promote把重複有用的部分整理成正式知識Procedure / Decision / Project / Synthesis
[S2][S11][S12]

05 / 隱私邊界

它是 internal，不是學生私資庫

Core repo 可以保存營運知識和去識別化流程，但不能保存學生可識別資料、secret、token、.env 或 runtime state。

secret 是不能公開的密鑰或登入憑證；.env 是常放設定和密鑰的檔案。學生私資、原始 IEP、完整 Gmail、完整私訊、session dump 都不應進入 Cyclone-Wiki Core。

可以放流程、決策、去識別化摘要、輸出 metadata、公開或 internal 專案脈絡。
不能放學生姓名、家長資訊、token、cookie、.env、資料庫 dump、完整 runtime state。
需要私密資料時Core 只放 routing shell 或指標，真內容留在 private vault 或原系統。
[S7][S2][S9]

06 / 哪些 Agent 可以讀與用

可讀不等於可任意改

MacBook coding agents 可以管理較正式的 wiki 工作；Mac mini runtime agents 原則上可以讀整個 wiki，但日常只寫 approved _inbox routes。

目前文件列出的 Agent 包含 Codex、Grok CLI、Cursor、OpenClaw、Hermes、Aurelion、Bahamut、OpenAB。Hermes、Aurelion、Bahamut、OpenClaw 主要在 Mac mini 或 runtime 任務裡使用 wiki。

角色可以做什麼主要限制
MacBook coding agents寫 inbox capture，也可在 wiki 管理情境整理正式 note不能寫 student-private；非管理情境優先只寫 inbox
Mac mini agents讀完整 wiki，日常寫 _inbox Source captures不能在 routine operation 改 AGENTS、procedure、decision、project
Aurelion外部知識與 Info Collect capture要有來源，不保存全文或私資
Bahamuthandoff、dispatch、daily summary capture不保存完整 transcript
OpenClaw研究、daily/weekly digest、外部探索legacy Obsidian 只當 read-only fallback
OpenABMac mini coding retrospective；規劃成 GitHub development radar ownerOpenAB Pod repo 尚未建立，屬後續規劃

07 / 寫入規則

Read wide, write narrow

Cyclone-Wiki 的 Agent 寫入原則是讀得廣、寫得窄。這可以讓 Agent 充分理解背景，又不會亂改核心規則。

Level 0 到 Level 3 是治理層級：不是每件小事都要開 issue，但會影響正式知識、runtime、Agent 行為或 automation 的變更，要有更嚴格的流程。

Level白話說明是否需要更嚴格流程
0沒有可重用知識，就不要寫噪音不用
1普通 capture，先進 _inbox跑 lint、privacy scan，可批次 commit
2正式 wiki curation，例如 Procedure、Decision通常要 issue 和完整驗證
3runtime、Agent 行為、automation一定要 issue、驗證、留下 evidence

從共同記憶，走向可複製的工作環境

目前已經有入口文件、搜尋政策、驗證腳本、capture wrapper；接下來的重點是 skill sync、HTML briefing workflow、agent memory radar 和 GitHub development radar。
