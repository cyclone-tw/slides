03 Speaker

珊迪分享：讓收藏真正變成自己的知識

痛點很明確：收藏當下覺得有用，但幾天後就忘了；沒有輸出與應用，收藏最後只會變成資料堆積。

珊

核心設計

珊迪設計的「收藏鼠」是一隻放在雲端伺服器上的 Hermes agent。Discord Bot 是它的身體與嘴巴，使用者把連結或文字貼給它，它先讀內容並做第一次整理，再把資料放入倉庫。

每天晚上，agent 會整理當天收藏資料的知識重點，並提供三個簡單問題讓使用者複習。隔天早上，它再提出更深層的問題，例如「這個資訊可以用在我哪些情境？」使用者回答後，agent 會把原始重點與個人回答整合成個人化心得。

踩坑一：需求一開始太模糊

最早只想做「丟連結就收藏」，後來才逐步釐清：資料從哪裡來、放在哪裡、誰要讀、最後輸出到哪裡。她的心得是不要一開始就想串完整功能，先拆資料流。

踩坑二：開發環境與部署環境不一致

Windows、本機環境、Zeabur 伺服器、Hermes agent 安裝都會造成卡關。她提醒初學者要先了解部署需要哪些環境，並盡量貼近正式部署環境。

踩坑三：串接不是單點問題

Discord 不回、cron job 沒跑、Notion 欄位對不上，常常不是某個工具壞掉，而是整條鏈缺少必要設定。debug 時要看整條資料鏈。

安全提醒

珊迪特別提醒：GitHub repo 可以記錄開發過程、版本與經驗，讓未來的 agent 能回頭看；但絕對不能把 `.env`、API key、token、private key 等密碼類資訊推到雲端。她建議一開始就把這條規則寫進 `AGENTS.md` 或 agent 的工作規範。

自動化系統不只是把工具接起來，而是建立一條清楚、可排查、可維護，而且安全的資料流程。

04 Speaker

Cyclone 分享：把 AI agent 接進工作與開發流程

Cyclone 的分享聚焦在近兩三個月的實作：從「需要一台 24 小時跑的主機」開始，逐步把 VPS、Zeabur、Discord、Notion、Google Drive、GitHub 與個人 dashboard 串起來。

Cy

從本機到雲端

一開始看到許多文章建議買 Mac mini 當常駐主機，但成本與空間都不容易。後來改用 VPS / Zeabur 這類雲端伺服器，讓 agent 可以 24 小時運行，再透過 SSH 與部署流程把資料與服務放上去。

這段過程也帶出一個關鍵觀念：如果 agent 只是照死規則跑，就失去「代理人」的意義。真正有價值的是讓 agent 能理解使用者的行為模式、期待樣式，並在開發過程中逐步修正。

05 Principles

兩段分享整理出的共同原則

1. 先畫資料流，再做自動化

先釐清資料從哪裡來、存在哪裡、誰讀取、如何輸出。沒有資料流，就會在串接工具時一直改版。

2. debug 要看整條鏈

Discord 沒回覆、cron job 沒跑、Notion 沒寫入，可能是 token、欄位、權限、排程或部署環境其中一段出了問題。

3. agent 需要工作規則

`AGENTS.md` 或類似文件不是形式，而是讓 agent 知道怎麼做事、怎麼紀錄、哪些東西不能碰。

4. 安全規則要一開始寫清楚

`.env`、API key、token、private key 都不能推上 GitHub。安全規則不能等出事後才補。

5. 小步交付比一次做完有效

一次開一個 issue、處理一段功能、用 PR 驗收，可以讓 AI 更聚焦，也比較容易追蹤進度。

6. 共學的價值來自互看與互問

每個人的題目不同，反而能看到不同思路；別人的成果、卡點與提問，會變成自己的下一個 idea。
