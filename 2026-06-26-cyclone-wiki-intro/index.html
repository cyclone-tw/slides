不是從零發明，而是把兩種已被驗證的做法拼在一起。左＝團隊共用規則，右＝個人與 Agent 工作日誌。

怎麼管理

四個等級 — 要不要寫、要不要開會

控制「什麼值得進 Wiki」的門檻。等級越高，越需要人審、越不能亂改。

等級白話舉例
L0 不寫閒聊、問候「早安」「今天天氣好」→ 不進知識庫
L1 收件匣值得留，先丟草稿區今天 coding 有學到教訓 → 先寫 inbox
L2 審核升格變正式團隊規則草稿升格成 SOP → 要開 issue、人看過
L3 改系統動 Agent 排程與自動化改日終日誌怎麼跑 → 最慎重、要驗證

台階越高 → 流程越正式 · 推送前必跑 wiki-lint.sh + privacy-scan.sh

現場 Demo · 約 10 分鐘

同一天的小故事

用「早上收 URL → 中午寫 code → 下午派工 → 晚上日誌」串起來。箭頭後是筆記最後躺在 Wiki 哪一格。

1
早上 · Aurelion 收 URL → Private/_inbox/info-collect/你在 Discord 貼文章連結 → 登記成 Markdown，放私人剪報櫃（不是只在聊天裡回「收到了」）
2
中午 · Cursor 寫回顧 → Core/_inbox/coding-sessions/macbook-cursor/寫程式結束 → 留工程日誌草稿，以後可升格成正式 SOP
3
下午 · Bahamut 交接 → Core/_inbox/agent-captures/派工單：「請 Cursor 改 README」→ 寫進 Core，不是只在 Discord @ 人
4
隔天開工 · 讀取read-pack = 自動打包「本週重點 + 工作桌 + 近日日誌」給 Agent 開工看；preflight = 任務需要查舊案時才搜尋整本 Wiki
5
晚上 · 日終日誌Agent 自己判斷今天值不值得寫；沒事回 [SILENT]（安靜不寫），有則寫 session log 並在 Discord 貼 Wiki 路徑 + 一行摘要
6
隨時 · Dashboard /wiki把 Wiki 匯成網頁卡片給人看——唯讀，改內容仍回 Wiki 正規流程
Demo 名詞： dry-run = 試跑、不真的寫檔，只看會寫到哪； capture = 走櫃檯登記寫入； [SILENT] = 今天沒值得留的，日誌跳過。

指令備忘（建議 dry-run 試跑）

export CYCLONE_WIKI_ROOT="$HOME/Cyclone-System/cyclone-wiki"
cd "$CYCLONE_WIKI_ROOT"

# 1 Aurelion
scripts/macmini-wiki-capture.sh --dry-run \
  --surface private --agent Aurelion --kind info-collect \
  --slug demo --title "Demo URL" \
  --source-url "https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f" \
  --body-file /tmp/demo-body.md

# 4 讀取
scripts/agent-read-pack.sh --agent Aurelion --topic "demo"

# 6 Dashboard

常見問題

跟 Notion 差別？
Wiki + Git 是唯一真相；Notion 可以當鏡像或給外人看，但不取代 Wiki。
會洩漏隱私嗎？
推送前會跑 privacy scan；學生敏感資料不進 Core，放 Private 教育 vault。
一定要裝 Tolaria 嗎？
不必。Tolaria 是可選的 Wiki 閱讀器，用 VS Code 或 GitHub 也能看。
QMD 是什麼？
本機全文搜尋，像圖書館檢索——Agent 需要查舊資料時才用，不是每次醒來跑一遍。
capture 櫃檯是什麼？
統一的「寫入櫃檯」腳本。所有 Agent 日常寫入都走這裡，避免各自改檔造成混亂。
