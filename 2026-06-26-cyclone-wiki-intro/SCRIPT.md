## 第 1 段｜封面（約 1 分鐘）

大家好，今天用大概二十分鐘介紹 **Cyclone-Wiki**。不用懂程式也沒關係，你只要記得一件事：

**這是給 AI 助理用的「不會消失的筆記本」。**

我們每天在 Discord 跟 Aurelion、Bahamut 聊很多，但關掉視窗，對話就沒了。Wiki 要回答四個問題：

1. **什麼值得留？**
2. **寫在哪？**
3. **誰來寫？**
4. **之後怎麼找回來？**

前半段講觀念，後半段我會現場示範各種 Agent 怎麼寫進去。有問題隨時舉手。

## 第 2 段｜為什麼需要 Wiki？（約 2 分鐘）

**（可先問聽眾）** 有沒有過：上週跟 AI 聊完的結論，這週再問，它像沒發生過？

**指左邊圖 Discord：** 像會議室白板便利貼，下班就擦了——我們叫 **Ephemeral（暫時的）**。

**指右邊 Cyclone-Wiki：** 像公司活頁夾加圖書館——可搜尋、有版本、可審核——**Durable（持久的）**。

**三個原則（請聽眾記）：**

1. **Wiki 優先** — 該留的不要只停在聊天。
2. **可以廣讀、謹慎寫** — Agent 可查很多；寫入要走「統一櫃檯」，不能隨便改正式規則。
3. **人和 Dashboard 同一套** — 筆記標籤，儀表板也看得懂。

**轉場：** 我們不是憑空發明，下一段講兩條設計靈感。

## 第 3 段｜兩條路線（約 2 分鐘）

**指灰色說明框：** 先解三個名詞——Tolaria = 正式筆記格式精神；K 大 Wiki = Agent 幫你維護 Markdown；QMD = 需要時才用的本機搜尋。

Wiki 是 **同一本活頁夾**，隔成兩邊，因為「公司規則」和「個人筆記」本來就該分開。

**Core（Tolaria 精神）— 公司手冊**

- 流程、決策、專案現況
- 每份筆記有類型、審核狀態
- 回答：我們團隊 **怎麼做、為什麼這樣做**

**Private（K 大 LLM Wiki）— 個人研究筆記**

- 收網址 → 整理 → 摘要
- Agent 維護互相連結的 Markdown
- 回答：我個人、各 Agent **最近在忙什麼**

**指下方 Git 一條線：** 同一個專案 `cyclone-tw/cyclone-wiki`，不是兩套系統。將來私人筆記若變成通用規則，可「升級」到 Core，但要審核。

**轉場：** 打開活頁夾看裡面有哪些分頁。

## 第 4 段｜資料夾地圖（約 2 分鐘）

這頁是地圖，**記用途，不用背路徑**。

**Core（青色）：**

- `procedure` = 怎麼做（SOP）
- `decision` / `project` = 為什麼、現在進度
- 黃色 `_inbox` = **收件匣**，新東西先丟這
- `coding-sessions` = 寫程式的回顧草稿
- `agent-captures` = Agent 之間的交接單、派工紀錄

**Private（橘色）：**

- 生活、教育
- Aurelion 收的網址 → info-collect
- 每個 Agent 的 `working.md` = **工作桌便利貼**
- `agent-sessions` = 每日日誌

**最下面：** 大檔案放 Google Drive，Wiki 只放 **索引卡**。

**轉場：** Private 的資料怎麼從亂丟變有條理？K 大式迴圈。

## 第 5 段｜K 大式迴圈（約 1.5 分鐘）

用 **收信** 比喻：

1. **收集** — 好文章、決定，先丟 inbox（待處理）
2. **整理** — 拆重點、標籤
3. **摘要** — 給未來的自己或同事一段話
4. **升級（可選）** — 變團隊規則才搬 Core，**要審核**

大部分新東西停在 inbox 是 **正常的**，代表沒把草稿當聖旨。

**轉場：** Agent 記憶還分溫度。

---

## 第 6 段｜Hot / Warm / Cold（約 2 分鐘）⭐ 常被誤解

**先破迷思：** Wiki ≠ 每次醒來整本讀一遍。

| 比喻 | 溫度 | 內容 |
|------|------|------|
| 口袋小抄 | Hot | Agent 出廠規則，很小很穩 |
| 桌面便利貼 | Warm | 本週重點、working.md、近日日誌 |
| 圖書館書架 | Cold | 整個 Wiki，**需要時才搜** |

**指圖上方：** Discord 當下對話比 Hot 還熱，但關掉就沒了——該留的要用 capture 寫進 Wiki。

**轉場：** 對到實際抽屜 Z0–Z3。

---

## 第 7 段｜Z0–Z3（約 1.5 分鐘）

**先講表在幹嘛：** 上一頁是溫度；這頁是「筆記放哪、開工先翻哪」。Z0–Z3 = 四個抽屜。表格右欄「生活比喻」= 像什麼、什麼時候才翻。

| 抽屜 | 放什麼 | 比喻 | 溫度 |
|------|--------|------|------|
| Z0 | Core 正式筆記（SOP、決策） | 圖書館參考書——要查規則才翻 | Cold |
| Z1 | startup-brief（Cyclone 現在忙什麼） | 門口本週重點告示——開工先看 | Warm |
| Z2 | Private 生活/教育 | 個人置物櫃——相關任務才開 | Cold |
| Z3 | 各 Agent working.md、日誌 | 桌上便利貼——我最近在幹嘛 | Warm |

**指流程圖：** 開工順序 Z1 → Z3 → 需要才搜 Z0。腳本是自動翻抽屜的工具。

**轉場：** 寫入要不要每次都開會？有分級。

---

## 第 8 段｜治理四等級（約 1.5 分鐘）

**指表格舉例欄：** 用生活例子記門檻，不用背代號。

| 等級 | 白話 | 舉例 |
|------|------|------|
| L0 | 閒聊 → 不寫 | 「早安」不進知識庫 |
| L1 | 值得留 → 先丟 inbox | coding 有教訓 → 先寫草稿區 |
| L2 | 升格正式 SOP → 要審核 | 草稿變團隊規則 → 開 issue、人看過 |
| L3 | 改 Agent 排程 → 最慎重 | 改日終怎麼跑 → 要驗證證據 |

推送前 **lint**（格式）+ **privacy scan**（個資）= Agent 自動寫入的安全帶。

**轉場：** 誰在寫？Aurelion、Bahamut、Cursor…

## 第 9 段｜各 Agent 分工（約 2 分鐘）

**指表格最右欄「在做什麼」：** 記崗位，不用背路徑。

| 角色 | 在做什麼 | 寫到哪 |
|------|----------|--------|
| Aurelion | 你丟 URL → 收進個人剪報櫃 | Private |
| Bahamut | 專案經理發交接單 | Core |
| Cursor 等 | 寫完程式留工程日誌 | Core coding-sessions |
| OpenClaw | 生活教育助理 | Private（落地中） |

**指 capture 櫃檯圖：** 像公司報帳要走會計櫃檯——所有寫入走同一腳本，不能隨手改檔。橘→Private，青→Core。

晚上 **日終日誌**：Agent 自己判斷要不要寫；沒事就安靜。

**轉場：** 進 Demo。

## 第 10 段｜Demo（約 8–10 分鐘）⭐

**Demo 開場：**  
「假設今天 Cyclone 早上丟 URL、中午寫程式、下午派工，看筆記怎麼一筆一筆進 Wiki。」

### 步驟 1｜Aurelion 收 URL（約 2 分）

「我在 Info Collect 貼 K 大 LLM wiki 文章。Aurelion 走櫃檯登記，不是只在 Discord 回一句。」

跑 `macmini-wiki-capture.sh --dry-run` …（或指已存在的檔案）

**指 stdout 路徑：** `Private/_inbox/info-collect/`  
**強調：** 私人收藏走 Private。

### 步驟 2｜Cursor 寫回顧（約 2 分）

「中午寫程式結束，留一段回顧 → Core coding-sessions。」  
**對比：** 剛才 Private，這是 Core 工程日誌。

### 步驟 3｜Bahamut 交接（約 1.5 分）

「Bahamut 發任務單給 Cursor → Core agent-captures，不是只 @ 人。」

### 步驟 4｜讀取（約 1.5 分）

「隔天開工，Agent 不會亂翻整本 Wiki。**read-pack** = 有人幫你整理好『門口告示 + 桌上便利貼 + 最近日誌』一疊；**preflight** = 任務要查半年前的決策，才去圖書館搜。」

### 步驟 5｜日終日誌（約 1 分）

「晚上排程，Agent **自己判斷**；沒事 **[SILENT]**（安靜不寫），有就寫 session log + Discord 兩行 Wiki/Summary。」

### 步驟 6｜Dashboard（約 1 分）

「Wiki 是原文；匯出 JSON → /wiki 卡片，唯讀。」

**備援：** 若終端機不可用，改指 Git 裡真實檔案或播放錄影。

---

## 第 11 段｜Dashboard（約 1.5 分鐘）

**指灰色說明框：** Wiki（Git）= 公司正本；Dashboard = 影印成卡片掛牆上；JSON = 中間那包卡片資料。

Wiki = **唯一真相**（Git）。Dashboard = **櫥窗**（唯讀網頁卡片）。

好處：非工程同事不用翻 Git。v1 **唯讀**，要改仍回 Wiki 正規流程。

有開 `/wiki` 可指 Knowledge feed、Agent pulse。
