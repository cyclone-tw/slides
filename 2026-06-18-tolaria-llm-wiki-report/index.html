Part AProblem Definition
02 · 問題定義

AI-first LLM Wiki 不只是「多一個筆記工具」

人類可讀

Markdown、清楚 metadata、穩定命名，讓 Cyclone 不靠工具也能閱讀與修正。

Agent 可維護

入口規則、routing、schema、lint 都寫成 agent 能執行的合約。

Git 可審計

每一次新增、升格、修正都有 diff；知識庫不是黑盒 SaaS 狀態。

傳統 PKM 重點是人的整理；LLM Wiki 重點是人與 agent 共同維護。
雲端 wiki 重點是協作 UI；LLM Wiki 重點是檔案、權限、路由與可追溯脈絡。

Part ATolaria Positioning
04 · Tolaria 定位

Tolaria 的核心不是 UI，而是 Desktop Markdown 的工作邊界

01
Desktop Markdown資料在桌面，不先變成雲端資料庫。
02
files-first檔案路徑、frontmatter、wikilink 是原始真相。
03
git-first修改能被 review、diff、rollback，而非只剩操作紀錄。
04
offline-first離線可讀寫；同步是加值，不是存取前提。
05
agent-ready把 agent 的入口、工具與禁區寫進 repo。

定位結論：Tolaria 比較像「給 LLM 的 Markdown IDE」，不是 Notion 或 Obsidian 的單純替代品。

Part ADesign Principles I
05 · 設計原則 上

上半場：把「筆記」升級成可被 agent 操作的知識物件

Types as lensesnote type 不是分類癖；它是閱讀、搜尋、驗證與升格時的鏡片。
AI-first graphgraph 不只是給人看連線，而是讓 agent 能判斷鄰近脈絡與缺口。
AGENTS.md每個 repo / vault 的入口合約：可做什麼、不能碰什麼、如何驗證。
Disk-first先讓檔案系統成立，再讓 UI、MCP、QMD、search index 吃同一份真相。
原則不是口號，是約束 agent 的操作面05 / 25
Part ADesign Principles II
06 · 設計原則 下

下半場：讓工具可以替換，讓知識不被工具綁架

Tool-agnostic

Codex、Claude、Gemini、Hermes 應讀同一套規則，而不是各寫一套 prompt。

Convention over config

路徑、metadata、命名、升格流程固定，降低每次開工的協商成本。

Neighborhood

agent 不只找單篇，而是找鄰近筆記、反向連結與同型內容。

Multi-vault

長期知識、教育私密、legacy 來源分層，不把敏感內容混進公開 core。

好的 LLM Wiki 不追求「看起來聰明」，而是讓每次修改都有邊界、有來源、有下一步。

工具可替換，合約不可缺席06 / 25

Part AData Model
08 · 資料模型

Markdown 是容器；frontmatter 與 wikilink 才是操作界面

每篇 note 同時要服務三種讀者：人、agent、Git reviewer。資料模型要讓三者看到同一件事。

frontmatter 存 type、status、source、privacy、promotion metadata。
[[wikilink]] 建圖，backlink 幫 agent 補足鄰近脈絡。
Source原始捕捉：session log、coding retrospective、digest、reference 摘要。
Synthesis整理後可重用的知識：主題總結、跨來源觀察、模式。
Procedure可重複執行的步驟：命令、驗證、失敗處理。
Decision需要長期遵守的架構與治理決策。
Markdown + frontmatter + wikilink graph08 / 25
Part AEditing Experience
09 · 編輯體驗

好的編輯器不是把 Markdown 藏起來，而是讓不同內容選對模式

BlockNote

適合一般段落、callout、清單與快速 rearrange；讓非工程內容編輯更接近文件。

CodeMirror

適合 frontmatter、code path、Mermaid、MCP tool spec；保留精準文字控制。

Rich Blocks

Mermaid、tldraw、math 可以在 viewer 層渲染，但原始資料仍回到 Markdown。

切換 editor mode 時，不能破壞 frontmatter 或 wikilink。
任何 rich view 都應該能退回 plain text，避免工具失效時知識也失效。
Block editing for humans · text fidelity for agents09 / 25

Part BDecision
15 · Cyclone 決策

決策：agent-first；Tolaria optional

現在就做

把 Cyclone-Wiki core vault、inbox routing、metadata schema、lint gate 建起來。

可以試用

Tolaria 若能穩定讀寫 Markdown/Git，就作為桌面 UI 與 graph explorer。

不能依賴

長期知識層不可綁死任何單一 app；agent、CLI、Git 才是底層合約。

優先投資 source-of-truth：路徑、metadata、privacy、promotion、Git。
UI 是加速器，不是治理層；治理層要能在沒有 UI 時運作。
Decision: build the wiki contract first15 / 25
Part BVault Layers
16 · Vault 三層

Core / Education Private / Legacy Obsidian：不要把所有知識混成一鍋

Corecyclone-wiki-core：長期、可重用、可讓 agent 讀寫的正式知識層。
Education Private特教工作、學生、家庭、敏感個案，只能在更嚴格的 private boundary 中處理。
Legacy Obsidian舊 vault 作為 read-only source workspace；不再當新的長期知識真相。
Core 只收可升格、可審計、可重用內容。
Private 與 legacy 內容可被引用或摘要，但不能無條件搬進 core。

Part BAGENTS.md Contract
17 · AGENTS.md

AGENTS.md 是入口合約，不是備忘錄

讀什麼

入口索引、Soul、capabilities、privacy、search policy。

寫哪裡

一般 agent 只能先寫 _inbox/，不能直接改 formal note。

怎麼驗證

metadata schema、link check、privacy-scan、Git diff。

不能做什麼

不能洩漏 secret、不能覆寫人類內容、不能跨 boundary 搬敏感資料。

inbox-first 的目的不是拖慢工作，而是讓 agent 的輸出先有隔離區，再由治理流程決定是否升格。

入口合約要短、明確、可執行17 / 25

Part BInbox Flow
19 · Inbox 流程

捕捉 → 審核 → 升格：把 agent 輸出變成可靠知識

Capture
先寫 source note保留原始上下文、目標、完成內容、驗證。
Lint
基本格式檢查frontmatter、title、status、tags、必要章節。
Review
人工或 agent 審核判斷是否可重用、是否涉及 privacy。
Promote
升格 formal note整理成 Synthesis、Procedure、Decision 或 Project。
Audit
Git diff 留痕source note 保留，formal note 標記來源。
Inbox is a quarantine, not a trash bin19 / 25
Part BQMD Search
20 · QMD 搜尋

QMD 是 semantic search 外掛，不是新的 source-of-truth

Index

吃 Markdown、frontmatter、wikilink graph，建立可重建的 semantic index。

Retrieve

回傳 note path、摘要、關聯片段與信心線索，不回傳不可追溯答案。

Respect Boundary

搜尋必須遵守 privacy policy；private vault 不應被 core 查詢偷渡。

QMD 解決「找得到」；AGENTS.md 解決「找到後能不能動」。
semantic search 不能取代 Git diff、source note 或 promotion review。
Semantic retrieval with provenance20 / 25

Part BQuality Gates
23 · 品質閘門

wiki-lint + privacy-scan：先擋錯，再談自動化

Metadata

必填 title、type、status、created、updated、tags、source_agent。

Links

檢查 broken wikilink、孤兒 note、重複 title、錯誤 path。

Privacy

偵測學生、個案、token、secret、private path 外流跡象。

Promotion

升格 formal note 時確認 source、review、decision rationale。

Level 1 可以快速 capture，但仍需通過基本 schema。
Level 2/3 必須保留 issue、review 或 runtime evidence，不能只靠 agent 自我宣稱。
Automation without gates creates knowledge debt faster23 / 25
Part BRoadmap
24 · 路線圖

先建立穩定知識管線，再追求漂亮桌面 UI

短期 · 2–4 週

  1. 固定 core vault 目錄與 type schema。
  2. 完成 AGENTS.md 入口與 inbox-first 規則。
  3. 建立 coding retrospective / digest 模板。
  4. 跑 wiki-lint、privacy-scan、broken-link check。
  5. 把 QMD 搜尋接成 read-only 輔助。

中期 · 1–2 季

  1. 導入 promotion workflow 與 review dashboard。
  2. 做 MCP read/search/write 最小工具面。
  3. 讓 Hermes 負責 routing 與 scheduled digest。
  4. 評估 Tolaria 作為 desktop graph/editor。
  5. 把高價值 inbox notes 升格成正式 wiki。
Roadmap is contract-first, UI-second24 / 25
Part BClosing
25 · 結語

三條建議：讓 Cyclone-Wiki 先成為可靠系統，再成為漂亮產品

01

先定 source-of-truth

Markdown + Git + metadata schema 是底層；UI、QMD、MCP 都只是讀寫這份真相。

02

先 inbox，再升格

不要讓 agent 直接污染正式知識；capture 快，promotion 慢，這是治理節奏。

03

Tolaria optional

若成熟就接入；若不成熟，Cyclone-Wiki 仍能靠 agent、Git、QMD 與 Hermes 運作。

Q&A：下一步不是問「要不要用 Tolaria」，而是問「Cyclone-Wiki 的合約是否已經清楚到任何 agent 都能安全執行」。
